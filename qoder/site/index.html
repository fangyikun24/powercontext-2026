🧠 笔记智能摘要

示例笔记已存入 seekdb，可按关键词做中文全文检索；下方摘要展示整理后的要点结构

📖 原始笔记 (经济学原理)

边际效用递减规律是指随着某种物品的连续消费，消费者从每一额外单位的消费中获得的满足感会逐渐减少。这个规律适用于大多数商品和服务。举例来说，当你非常饿的时候，第一个汉堡带给你的满足感是最强的，第二个就没那么强了，吃到第五个可能已经不想吃了。这个规律对定价策略、需求预测都有重要意义。企业通常会提供折扣促销来鼓励消费者购买更多，因为边际效用递减意味着需要更低的价格才能让消费者对额外单位产生兴趣。

→

✨ AI 摘要要点

  • 定义: 连续消费同种物品，满足感逐渐降低
  • 应用: 定价策略、需求预测、市场营销
  • 实例: 饥饿时第一个汉堡最美味，后续逐渐减少
  • 商业启示: 促销折扣可提高边际消费量

技术实现：笔记与错题真的存进 seekdb

学习笔记、错题和复习记录没有写死在 HTML 里。本地服务用嵌入式 seekdb （MySQL 协议）保存三张表，检索走 ngram 中文全文索引并支持科目结构化过滤， 点击「这次答对了」会把复习动作写回 review_log。 本页下方每一组数字都取自 2026-10-29 的实际运行输出。

存储结构

  • notes：title / content / subject / tags，FULLTEXT ft_notes(content) WITH PARSER ngram
  • questions：subject / question / wrong_answer / correct_answer / knowledge_point / attempts / correct_count，FULLTEXT ft_questions(question) WITH PARSER ngram
  • review_log：question_id / correct / reviewed_at
  • 三张表均为 ORGANIZATION = HEAP，首次启动自动建表并写入 8 条笔记、6 道错题

接口

  • GET /api/health健康检查，返回 {"ok":true,"engine":"seekdb"}
  • GET /api/search?q=&subject=笔记全文检索 + 科目过滤
  • GET /api/questions?q=&subject=错题全文检索 + 科目过滤
  • POST /api/review写入复习记录，并累加 attempts / correct_count
  • GET /api/stats笔记、错题、复习条数与分科目正确率

运行说明

环境（已验证）

操作系统Windows 11

Python3.12.14

数据库驱动pylibseekdb 1.4.0.post2（嵌入式，无需 Docker）

客户端pymysql 1.2.3

服务端口127.0.0.1:8787

数据目录C:\Users\Public\StudyMateData\seekdb

启动与验证

# 在 qoder/ 目录下执行
python -m pip install -r requirements.txt

# 1. 一键验收（6 项检查，无需启动服务）
python run_demo.py
#   PASS：seekdb 检索 / 过滤 / 复习写回 / 统计全部可用

# 2. 启动本地演示服务
python backend/server.py
#   [server] http://127.0.0.1:8787

# 3. 接口级验收（7 项断言，另开终端）
python backend/verify_seekdb.py

两个硬约束：seekdb 数据目录必须是纯 ASCII 路径， 放在含中文的用户目录下会 seekdb_open failed: code=-1； 中文全文索引必须 WITH PARSER ngram，改回默认分词器后中文短语不再命中。

验证样例（2026-10-29 实测）

① 中文全文检索命中，返回真实 score 与耗时

GET /api/search?q=边际效用

count 1 · took_ms 5.95 · score 1.6996 · engine=seekdb；命中笔记《边际效用递减》（经济学）

② 换一个词，命中另一条数据

GET /api/questions?q=导数

count 1 · took_ms 3.28 · score 1.5535； 命中「求函数 f(x) = x²e^x 的导数」，已练 4 次 / 对 3 次

③ 科目过滤下推到 seekdb 执行

q=导数&subject=数学 → count 1
q=导数&subject=英语 → count 0

同一关键词换科目即无结果，说明 subject 条件由数据库执行， 不是前端数组筛选

④ 复习动作写回数据库

POST /api/review {"question_id":1,"correct":true}

attempts 4 → 5、correct_count 3 → 4； /api/stats 的 reviews 1 → 2。 在演示页点一次「这次答对了」后，页面提示已写入 seekdb：第 6 次练习， reviews 2 → 3，数学正确率 71.4% → 75%

验收脚本 backend/verify_seekdb.py 本次运行输出 7 项全部 PASS： engine 声明、两次检索的 score/took_ms、科目过滤、复习写回、review_log +1、分科目正确率变化。
