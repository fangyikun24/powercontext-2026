### 1.3.1 期间遇到的三个真实问题（记录在案）

`artifacts/records/llm-calls.jsonl` 保留了全部 3 次调用，前两次是失败重试：

| # | 现象 | 原因 | 处理 |
| --- | --- | --- | --- |
| 1 | `outcome: ok` 但响应为空 | M3 的 thinking 消耗了全部 16384 个输出 token（`thinking_tokens: 16383`） | 提高 `max_tokens` 到 32768，并发送 `reasoning: {"effort": "low"}` 抑制推理长度 |
| 2 | 返回 `"changes": []` | 模型声称「没有文件读取工具，无法产出完整文件」 | prompt 里直接附上目标文件的**完整当前内容**，并在 system prompt 中声明无需任何工具 |
| 3 | 成功（首次） | — | 产出 4762 字符、1 个文件的完整新内容 |
| 4 | 成功（复跑） | — | 清空 `state/` 后重跑，产出与第 3 次逐字节相同 |

另外两个 API 事实：

- **M3 系列不允许关闭 thinking**：`thinking: {"type": "disabled"}` 返回
  `400 invalid params ... requires adaptive thinking`，只能用 `reasoning.effort` 调节；
- **两类密钥不能混用**：`sk-api-` 走积分/钱包余额（实测 402），
  `sk-cp-`（Coding Plan）走 M Plan 订阅额度（实测 200）。本次使用的有效密钥是后者。

### 2.2 表与索引（真实 DDL）

```sql
CREATE TABLE IF NOT EXISTS sdd_materials (
    material_id     CHAR(40)     NOT NULL,
    project         VARCHAR(128) NOT NULL,
    kind            VARCHAR(16)  NOT NULL,
    path            VARCHAR(512) NOT NULL,
    symbol          VARCHAR(255) NOT NULL DEFAULT '',
    start_line      INT          NOT NULL DEFAULT 0,
    end_line        INT          NOT NULL DEFAULT 0,
    title           VARCHAR(512) NOT NULL DEFAULT '',
    body            LONGTEXT     NOT NULL,
    content_hash    CHAR(64)     NOT NULL,
    updated_at      BIGINT       NOT NULL,
    searchable_text LONGTEXT     NOT NULL,
    PRIMARY KEY (material_id),
    KEY ix_sdd_project_kind (project, kind),
    KEY ix_sdd_path (path(191))
) DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_bin;

CREATE FULLTEXT INDEX ix_sdd_fts
    ON sdd_materials (searchable_text) WITH PARSER SPACE;
```

索引实际存在（来自 `information_schema.statistics`）：

| index_name | index_type | column |
| --- | --- | --- |
| `ix_sdd_fts` | **FULLTEXT** | `__word_segment_30_…`, `__doc_id_…`（seekdb 内部列） |
| `ix_sdd_path` | BTREE | `path` |
| `ix_sdd_project_kind` | BTREE | `project`, `kind` |
| `PRIMARY` | BTREE | `material_id` |

> seekdb 会把 `FULLTEXT ... WITH PARSER SPACE` 编译成内部 `__word_segment_*` / `__doc_id_*` 列，
> 所以 `information_schema` 里看到的列名不是 `searchable_text`，这是预期行为。

```sql
SELECT kind, path, symbol, start_line, end_line, title, body, content_hash,
       MATCH(searchable_text) AGAINST (? IN NATURAL LANGUAGE MODE) AS score
FROM sdd_materials
WHERE project = ? AND kind IN (?, ?, ?)
  AND MATCH(searchable_text) AGAINST (? IN NATURAL LANGUAGE MODE)
ORDER BY score DESC, path, start_line
LIMIT ?;
```
